# THAOS Lite — первый запуск на GitHub Pages и Firebase

## Главное

- **GitHub Pages** публикует HTML/CSS/JS и изображения. Для демонстрации публичных страниц **Firebase не требуется**.
- **Firebase Authentication** нужен для входа, **Cloud Firestore** — для профилей, групп и сохранённых изменений Редактора.
- **Cloud Storage for Firebase** нужен **только если Редактор будет загружать арты из браузера**. Изображения, включённые в ZIP в папке `assets/`, работают на GitHub Pages без Storage и без отдельного API.
- Конфигурация Firebase уже находится в `js/firebase-config.js` и указывает на `thaos-beca8`. Это публичные идентификаторы, не пароль. Используйте этот проект, если он принадлежит вам; при необходимости замените значениями своего проекта.

## Шаг A: увидеть публичный THAOS (без регистрации)

1. Сделайте резервную копию нынешнего репозитория или создайте новый **тестовый** репозиторий на GitHub, например `thaos-preview`.
2. Распакуйте `THAOS-Lite-Stable.zip`. В корне репозитория должны оказаться `index.html`, `core.html`, `css/`, `js/`, `assets/`, `data/`. **Не загружайте только ZIP** и не делайте лишнюю вложенную папку вокруг сайта.
3. На GitHub откройте **Settings → Pages**. Выберите **Build and deployment → Source: Deploy from a branch → Branch: main → Folder: /(root)**, затем **Save**.
4. После завершения публикации откройте адрес, который покажет GitHub Pages (обычно `https://<username>.github.io/<repository>/`).
5. Проверьте главную страницу, `classes.html`, `races.html`, `core.html`, `core-movement.html`, `world.html` и обычные переходы без анимации между ними. Арты из `assets/` должны загрузиться без Firebase.

## Шаг B: Firebase для регистрации и данных

1. Откройте [Firebase Console](https://console.firebase.google.com/), выберите свой проект. Сверьте его `projectId` с `js/firebase-config.js`.
2. В **Authentication → Sign-in method** включите **Email/Password**.
3. В **Authentication → Settings → Authorized domains** добавьте фактический домен вашего GitHub Pages (`<username>.github.io`, без пути `/repository/`). Если используется собственный домен, добавьте и его.
4. В **Firestore Database** создайте базу `(default)`, если её ещё нет. В **Firestore → Rules** опубликуйте **полностью** файл `firestore.rules` из архива. Не подменяйте его тестовым `allow read, write: if true`.
5. Зарегистрируйтесь на `auth.html` и убедитесь, что открылся кабинет игрока; обновите страницу и проверьте, что вход сохранился. Затем попробуйте выйти из аккаунта и войти снова.
6. Для прав **Редактора** скопируйте свой Firebase Authentication UID. В Firestore Console создайте **`siteAdmins/{ваш_UID}`** с полем **`enabled` (boolean) = true**. Создавайте эту запись только через доверенную консоль, не через пользовательский интерфейс сайта.
7. Откройте `admin.html`, затем измените тестовый заголовок, опубликуйте и проверьте публичную страницу. Данные пишутся в `siteContent`, а не в исходные HTML-файлы.

## Шаг C: загрузка артов через Editor (позднее)

1. Для новых загрузок через браузер нужен **Cloud Storage for Firebase**. На 2026 год он требует тариф **Blaze** с привязанным биллингом даже при использовании бесплатных квот. Прежде чем включать, проверьте стоимость, лимиты и выставьте бюджетные уведомления.
2. Включите Storage и опубликуйте `storage.rules`. При необходимости выдайте служебное разрешение Firestore для проверок прав из Storage Rules согласно подсказке Firebase Console.
3. Только после этого проверьте загрузку WebP из `admin.html`. Уже вложенные в ZIP арты из `assets/` не требуют Storage.

## Диагностика

- Сайт работает, но регистрация не работает: проверьте Authentication / Authorized domains / конфигурацию Firebase / console log.
- Регистрация работает, но сохранение запрещено: проверьте Firestore Rules и документ `users/{uid}`.
- Редактор показывает UID, но не открывается: отсутствует `siteAdmins/{uid}` с `enabled: true`.
- Текст редактируется, но арт не загружается: проверьте Storage, тариф Blaze и `storage.rules`.
- Анимация не проигрывается: проверьте системную настройку **«Уменьшение движения»**. При ней эффект специально отключён.
- Не открывайте сайт напрямую через `file://`. Для локального теста используйте `python -m http.server 8000` из корня проекта.

## Что пока не появится от одной публикации

Новые классы/пути и DIV-конструктор, полноценная роль обычного GM, самостоятельные городские страницы и расширенный бестиарий — это следующие этапы, а не функции текущей Lite-сборки.
