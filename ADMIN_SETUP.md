# THAOS Lite — Мастерская Редактора и Firebase

Актуальные шаги первой публикации см. в **`DEPLOY_FIRST.md`**.

Пакет содержит готовый интерфейс `admin.html`, редактор `js/admin.js`, публичный слой `js/cms-public.js`, стили и правила безопасности. **Действительный доступ и публикация в Firebase не активируются автоматически при распаковке архива.** Администратор должен включить сервисы и опубликовать Security Rules.

## 1. Разместить сайт

Загрузить содержимое этого архива (не родительскую папку) на существующий GitHub Pages или другой HTTPS-хостинг. В `js/firebase-config.js` уже записана публичная конфигурация проекта `thaos-beca8`; Firebase-паролей и служебных ключей в архиве нет.

Для теста локально запустить из корня `python -m http.server 8000` и открыть `http://localhost:8000/`. **Не открывать через `file://`**.

## 2. Включить Firebase

1. В Firebase Console включить **Authentication → Email/Password** (если ещё не включено).
2. Проверить наличие Firestore Database `(default)` и опубликовать **полностью весь** файл `firestore.rules` в Firestore → Rules. Он сохраняет прежние права игроков и добавляет отдельные `siteAdmins` и `siteContent`.
3. В Firebase Console создать Cloud Storage for Firebase, если не создан. Обратите внимание: Storage может потребовать подключения тарифного плана Blaze. В Storage → Rules опубликовать файл `storage.rules`. При первом использовании проверки роли в Firestore из Storage Rules консоль может попросить выдать сервису дополнительные разрешения на чтение Firestore.
4. В Authentication → Settings → Authorized domains убедиться, что добавлен домен вашего сайта.

## 3. Один раз назначить Редактора

1. Зарегистрироваться на опубликованном сайте обычным способом (`auth.html`).
2. В Firebase Console → Authentication → Users скопировать **UID собственного аккаунта**. Также его можно посмотреть в `admin.html` после входа.
3. В Firebase Console → Firestore → Data создать коллекцию `siteAdmins` и **документ с ID, равным вашему UID**. Добавить поле `enabled` типа `boolean` со значением `true`.
4. Убедиться, что документ был создан именно через доверенную Firebase Console / серверный Admin SDK: обычные пользователи не могут назначить себя Редактором.
5. Обновить сайт: у Редактора появится ссылка «Редактор» в навигации. Перейти в `admin.html`.

Если права не назначены, панель показывает сообщение и UID, но не даёт редактировать. Изменение HTML в браузере не даёт права записи: правила Firestore и Storage проверяют роль на сервере.

## 4. Как пользоваться

- Выбрать запись: модуль, расу, класс, регион или фон раздела.
- Менять заголовок, описание, параметры и иллюстрацию. Новое изображение из JPEG, PNG или WebP автоматически сжимается до WebP с максимальной геометрией 1680×1050 пикселей и максимумом 5 МБ.
- Для модулей правил доступны отдельные поля для заголовков, абзацев и пунктов существующей статьи. Сохраняются обычные текстовые значения: сложная HTML-разметка в изменённом блоке будет заменена на обычный текст, чтобы избежать внедрения кода.
- Нажать **«Опубликовать изменения»**. Для отмены изменений конкретной записи нажать **«Вернуть оригинал»**.
- Публичные страницы читают публикации из `siteContent`. Если Firestore временно недоступен или у записи нет публикации, показываются исходные статические тексты и изображения.

## 5. Что входит и что не входит

**Есть:** 8 модулей Core, новая страница передвижения, арты в карточках и на обложках статей, графитовые фоны каталогов, CMS для карточек, рас, классов, регионов, заметок мира, артов и текстов глав правил; защищённый вход Редактора и хранилище артов.

**Пока нет:** автоматического открытия/закрытия регионов отдельно для каждой игровой партии, визуального редактора карты и деревьев навыков, истории версий CMS, серверной проверки всех внешних правил мира, а также полностью произвольного редактирования структурированных описаний навыков каждого класса. Для таких функций потребуется отдельная модель данных и новые UI-компоненты.

## 6. Безопасность

Не добавляйте `enabled: true` в обычный `users/{uid}` — администраторская роль существует только в `siteAdmins/{uid}` и создаётся из консоли.

Не публикуйте приватный ключ сервисного аккаунта, Storage access tokens, секреты или пароли. Для публичных артов права чтения открыты, а загрузку по пути `site-assets/{uid}` разрешает только защищённая роль Мастера. Удаляйте ненужные загруженные изображения в Firebase Console при необходимости (замена арты в CMS не удаляет старый объект Storage).

## 7. Проверка после запуска

1. Без входа открыть `core.html` и `core-movement.html`: должны работать все карточки и демонстрация путешествия.
2. В обычном аккаунте без роли открыть `admin.html`: редактирование должно быть недоступно.
3. В админском аккаунте изменить описание модуля, нажать «Опубликовать», обновить `core.html` и страницу соответствующего модуля: новый текст должен появиться.
4. Загрузить новый арт, опубликовать, проверить его на странице.
5. Выполнить «Вернуть оригинал», убедиться, что исходные текст и арт снова видны.

При изменении исходных HTML/JS-файлов существующие сохранённые поля CMS могут продолжать переопределять новые значения; сбросьте запись, чтобы вновь использовать новые исходники.
