# THAOS Player System V1

**Основа:** существующий THAOS, 13 классов, 12 рас, карта, активности, 7 модулей Core, вход и профиль. Базовая версия скопирована, не переписана.

## Что доступно прямо сейчас

1. Регистрация / вход `auth.html`, настройки учётной записи `account.html`.
2. `player.html#characters`: 8 слотов персонажей, создание и правка; арты до ~80–115 КБ после автоматического сжатия и сохранения в Firestore; выбор классов и рас из исходных JS-данных; 3/5 базовых навыков на 1–3 уровнях; Путь на 4–6, 2/4 навыка к 6 уровню; Перелом на 7. Уровень можно менять; автосброс лишних выбранных способностей при снижении уровня.
3. Персонажи сохраняются под `/users/{uid}/characters/{id}`. Экспорт JSON или отдельного красивого HTML-листа (его можно открыть или распечатать как PDF).
4. `#group`: лидер создаёт группу с эмблемой и описанием, получает код `TH-XXXXXX`; игрок отправляет заявку по коду; лидер одобряет; состояние участников синхронизируется через Firestore; ранг вычисляется из среднего уровня персонажей. Не больше шести членов группы.
5. `#map`: существующая карта и 23 точки, лидер сохраняет местоположение и заметку, остальные читают.
6. `#tools`: разделы Торговля / Улучшения / Сундуки оформлены, но операции ЗАБЛОКИРОВАНЫ до реализации безопасного интерфейса Мастера. Никакого фиктивного списания и наград.
7. `#dashboard`: сводка, новости из `announcements` (только опубликованные, при их наличии), настройка добровольной email-подписки.
8. Портрет Жреца размещён в `assets/classes/art/priest.webp` (900×1350).

## Важно — что НЕ реализовано

- Реальная отправка email-рассылок **пока не включена**. Сохраняется только согласие в `/users/{uid}/settings/notifications`. Для доставки нужно подключить серверный сервис рассылки (или внешнего поставщика). Нельзя класть ключ почтового сервиса в статический сайт.
- Панель GM, присвоение GM прав, мутанты/бестиарий, редактирование чужого здоровья Мастером, казна и транзакции не открываются клиенту и пока не сделаны.
- Истинные классы / конкретные навыки уровней 8–10 пока не представлены утверждёнными данными. Перелом визуально открывается, но не добавляет неподтверждённых навыков.
- Автоматические формулы Здоровья/Защиты/Скорости и рост Маны ещё не утверждены; пользователь вводит значения вручную. Начальная Мана 5, в правилах стоимость заклинаний по Кругу.
- Изображения временно хранятся в сжатом виде в документах Firestore, что приемлемо для маленького тестового проекта, но не подходит для масштабного хранения медиа. Новый Cloud Storage требует тариф Blaze; пока не включайте тарификацию без необходимости.
- Обновления статистик группы следует тестировать с несколькими тестовыми аккаунтами. Достоверность боевых значений в этом MVP не защищена от самостоятельного изменения игроком. Позже действия Мастера и критичные операции потребуют серверной валидации.
- Рядом с группами нет полноценного каталога приглашений; заявка отправляется по ID и одобряется вручную.

## Запуск в GitHub Desktop

1. Откройте GitHub Desktop, войдите в нужный GitHub аккаунт через `File → Options → Accounts`.
2. `File → Clone repository…` → `ttoa-core` (или ваш репозиторий) → `Clone`.
3. Распакуйте ZIP и скопируйте **всё его содержимое**, без дополнительной вложенной папки, в локальную папку репозитория через `Repository → Show in Explorer`. Не удаляйте скрытую папку `.git`.
4. В GitHub Desktop: `Changes` → Summary `THAOS Player System V1` → `Commit to main` → `Push origin`.
5. GitHub → репозиторий → `Settings → Pages` → `Deploy from a branch`, `main`, `/(root)`. Убедитесь, что `index.html` лежит в корне.
6. Firebase Console → `Authentication → Settings → Authorized domains`: внесите фактический домен Pages (`имя.github.io`, без https и путей).
7. Firebase Console → **Firestore → Rules**: замените прежние правила новым файлом `firestore.rules` из этого ZIP и нажмите **Publish**. Без этого персонажи, группы и подписка не сохранятся. Проверьте правила в Rules Playground / Emulator перед публичным запуском.
8. `Authentication → Sign-in method`: Email/Password = Enabled.
9. Откройте опубликованный `auth.html`, зарегистрируйте тестовый аккаунт и проверьте Player System. Для теста групп используйте ДВА разных аккаунта в отдельных профилях браузера.

**Никогда не выкладывайте секретные service-account JSON файлы или API-ключи отправки писем.** `js/firebase-config.js` содержит только публичную конфигурацию web app `thaos-beca8`.

## Публикация новостей

В Firebase Console (с правами владельца проекта) можно создать вручную документ `announcements/{id}` с:

- `title`: строка, например `THAOS Player V1`;
- `body`: строка с сообщением;
- `published`: boolean `true`;
- `publishedAt`: timestamp.

Он появится у авторизованных игроков в `#dashboard`. Сайт не позволяет публиковать новости от лица игрока, что предусмотрено правилами безопасности. Для уведомлений по почте потребуется отдельная админская интеграция с законным механизмом отказа от рассылки.
