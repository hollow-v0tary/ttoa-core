# THAOS — Кабинет Руководителя V1

**Дата:** 26 ноября 2026 г.  
**Основа:** последняя THAOS Character Builder V2 с Core Math 1.2.  
**Роль:** «Руководитель», отдельно от будущей роли «Мастер».

## Что есть в Character Builder V2

Выбор снаряжения **уже присутствует** на шестом шаге «Атрибуты и экипировка»:
- два начальных набора для каждого из 13 действующих классов;
- возможность надевать/снимать предметы внутри выбранного набора;
- проверка занятой руки/слотов инвентаря;
- динамический пересчёт HP, маны, Защиты, Скорости, инициативы и урона оружия;
- сохранение выбранного набора и экипировки в Firestore при соблюдении действующих правил.

Пока **не реализовано**: свободная покупка любых предметов за стартовые монеты, полноценный торговый каталог, создание собственных вещей в конструкторе. Это сознательно не выдаётся за реализованную функцию.

## Новая версия: кабинет Руководителя

- `director.html`: **живой кабинет**, вход через Firebase Auth и проверка защищённого `siteAdmins/{uid}.enabled == true`. Без этого нельзя читать, создавать, обновлять или удалять редакторские записи.
- `director-demo.html`: **демонстрация без Firebase**, данные хранятся только в локальном браузере, с экспортом JSON. Примерные черновики «Пожиратель душ» и «Пепельник» доступны только в демоверсии.
- Раздел **Обзор**: быстрые ссылки и карточки управления.
- Раздел **Действующий контент**: поиск по классам, расам, правилам, регионам, переход к `admin.html?entry=...` для редактирования реальных публикаций. Это существующий Editor CMS, теперь обозначенный как редактор Руководителя.
- Раздел **Реестр разработок**: создание, редактирование, удаление защищённых черновиков **классов, рас, Путей, навыков, предметов, артефактов, правил, регионов, монстров и энкаунтеров**.
- Структурированная запись: тип, стабильный ID, название, краткая история, механика, стоимость, лимит применения, уровень, редкость, связь с родительским объектом, иллюстрация.
- **Редактор текстовых блоков**: заголовок, абзац, список; добавление, перемещение и удаление блоков; безопасный предпросмотр без исполнения пользовательского HTML.
- Статусы `Черновик`, `На проверке`, `Готово к публикации`.
- Экспорт и импорт всех записей реестра в JSON с базовой валидацией.
- Кнопка в `account.html` появляется только если разрешён доступ Руководителя.
- `firestore.rules`: добавлены защищённые правила для `directorDrafts`. **Существующие правила V1/V2 персонажей и партий сохранены**.

## Важное разграничение публикации

**Публикуются на действующем сайте** только правки существующих страниц через `admin.html` и коллекцию `siteContent` (эта функция была и в прежней CMS, теперь доступна из кабинета).

**Не публикуются автоматически** новые черновики из `directorDrafts`, в том числе со статусом `Готово к публикации`. Публичный справочник/конструктор пока использует статические `class-data.js`, `race-data.js`, `path-descriptions.js`, каталог экипировки и действующие публичные дельты. Для добавления **новых** классов/рас/предметов в игру понадобится отдельная безопасная миграция и интеграция данных. Не изменяйте напрямую ID существующих классов/рас — они используются в сохранённых персонажах.

Редактор блоков — не полноценное визуальное перетаскивание произвольных HTML DIV. Произвольный HTML/JS преднамеренно не поддерживается, чтобы не создавать XSS и ошибок в публичном сайте.

## Установка

1. Сделайте резервную копию существующего репозитория и текущих Firestore Rules в Firebase Console.
2. **Полный ZIP:** распакуйте содержимое поверх корня **существующего** репозитория GitHub Pages THAOS. Не создавайте новый репозиторий. Проверьте изменения через GitHub Desktop и Push origin.
3. В Firebase Console → Firestore Database → Rules сравните действующие правила и новый `firestore.rules`, сохраните чужие/поздние изменения, затем опубликуйте объединённую версию. **Один только файл на GitHub Pages правила не применяет.**
4. Выдайте роль через Firebase Console: документ `siteAdmins/{uid}`, поле `enabled: true` типа Boolean, где UID берётся из аккаунта Руководителя. Создавать роль может только администратор Firebase, не пользователь сайта.
5. Войдите под Руководителем и откройте `director.html` или ссылку в профиле. Демо доступно через `director-demo.html` и не требует входа.
6. Для обновления опубликованных текстов используйте «Действующий контент» → «Редактировать публикацию». Для подготовки Пожирателя душ/Пепельника — «Реестр разработок».

На Firebase **Spark** загрузка файлов через Firebase Storage может быть недоступна (в зависимости от настроек/тарифа). Используйте подготовленные картинки `./assets/...` и GitHub Pages или согласованный внешний процесс. Кабинет не обходит тарифные ограничения.

## Тесты

Успешно выполнены локальные проверки:

```bash
node --check js/director.js
node --check js/director-demo.js
python tests/check_director.py
python tests/check_site.py
node tests/check_builder_v2.js
node tests/balance-regression.cjs
```

Получено: `DIRECTOR STATIC PASS`, `Pages: 26, missing references: 0`, `THAOS Character Builder V2: 5040 checks, 0 errors`, базовый баланс-регрессионный тест пройден; CSS разобран синтаксическим парсером без ошибок.

**Не проверено:** реальная публикация Firestore Rules в вашем Firebase-проекте, чтение/запись под настоящей ролью, полноценный интерактивный браузерный smoke-test. Здесь локальный Chromium блокирует навигацию административной политикой (`ERR_BLOCKED_BY_ADMINISTRATOR`). Тест `tests/director_smoke.py` приложен, чтобы запустить его на вашей машине после распаковки. Не выдаём статическую проверку за E2E.
